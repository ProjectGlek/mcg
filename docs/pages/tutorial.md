# 📚 Как писать свои доки

Я тут накидал инструкций чтобы свои доки писать. Файлы .md — это текстовые файлы с дополнительными возможностями оформления. В папке `docs` лежат:
- `index.html` — файл движка, его трогаем для изменения внешки базы
- `pages/` — папка со страницами `.md`; главная страница находится в `pages/README.md`
- `_sidebar.md` — боковая панель с оглавлением. Строка с `-` задаёт пункт, каждые 2 пробела перед `-` добавляют один уровень вложенности
- `scripts/` — JavaScript скрипты сайта и демо
- `media/` — картинки и другие файлы для страниц
  
Все страницы перечислены в `_sidebar.md`. Чтобы добавить страницу, создай `.md` файл в `pages/` и добавь ссылку на него в `_sidebar.md`, например `pages/new-page.md`. Для родительского пункта с вложенными страницами создай отдельную страницу-заглушку, укажи её в родительской ссылке, а дочерние ссылки вложи отступами. Например, для группы «Ранние идеи» родительская страница — `pages/placeholder1.md`.

Ниже аишка напишет главные возможности оформления .md говна.

## 1. Работа с текстом и акцентами

Вы можете легко выделять важные мысли:
* Это **жирный текст** (заключается в две звездочки).
* Это *курсивный текст* (заключается в одну звездочку).
* Это ~~зачеркнутый текст~~ (заключается в две тильды).
* Можно делать `код или технические термины внутри строки` (заключается в обратные кавычки).

---

## 2. Списки и структурирование

### Обычный список (Маркированный)
- Первый пункт меню
- Второстепенный пункт
  - Вложенный подпункт (делается двумя пробелами)
  - Еще один подпункт

### Нумерованный список
1. Наступить в говно
2. Вытереть об траву
3. Повторить при необходимости

## 3. Выделение блоков внимания (Alerts / Callout, пока не работает, 4:23 на часах я спать) 

В Docsify встроены шикарные блоки для заметок, предупреждений и подсказок. Они создаются с помощью знака `>` в начале строки:

> **💡 ОБЫЧНАЯ ЗАМЕТКА**
> Сюда можно писать важные пояснения, которые не должны потеряться в общем тексте.

> [!NOTE]
> Современный синтаксис Docsify для стандартной инфо-заметки.

> [!WARNING]
> **ОПАСНОСТЬ НАХ!**
> Используйте этот блок, чтобы предупредить пользователя о критических ошибках или действиях, которые могут всё сломать.

## 4. Оформление кода и конфигов

Если вам нужно выложить кусок кода, команду для терминала или содержимое файла, оберните текст в три обратные кавычки ` ``` `. Docsify автоматически добавит подсветку синтаксиса и **кнопку «Copy»** в углу блока:

```bash
# Команда для быстрой отправки изменений в ваш гитхаб
git add .
git commit -m "обновил базу знаний"
git push origin master
```

А вот так будет выглядеть кусок конфигурационного файла (например, `json`):
```json
{
  "status": "working",
  "database": "docsify",
  "speed": "fast"
}
```

## 5. Таблицы данных

Если нужно структурировать информацию (например, права доступа или типы какашек), используйте вертикальные черточки `|`:

| Тип объекта | Описание | Уровень опасности |
| :--- | :--- | :---: |
| 🧻 Бумажки | Безопасны, используются для очистки | Низкий |
| 💩 Какашки | Требуют осторожности при обходе | **Критический** |
| 🛠️ Скрипты | Могут забаговаться, если забыть точку | Средний |
